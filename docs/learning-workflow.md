# 如何阅读、做题和实践

## 一、直接打开常驻网站

GitHub Pages 发布后，直接访问：

```text
https://painterdiri.github.io/Game-Development-Knowledge/
```

不需要启动本地服务器，也不需要安装 MkDocs。MkDocs 只用于维护者本地预览和构建检查。

## 二、网站自动记住学习位置

打开任意课程页面后，网站会自动记录最后阅读的页面、章节和滚动位置。下次进入首页会自动继续，不需要：

- 手工打勾；
- 填写 `progress.md`；
- 写学习日志；
- 初始化个人学习目录。

记录只保存在当前浏览器，不上传 GitHub。首页的“继续上次学习”区域可以立即继续、本次留在首页，或清除自动续学记录。

## 三、最高效的阅读顺序

1. 打开课程 `README.md`，确认课程解决的问题和出口能力；
2. 快速看 `lessons/00-course-map.md`，只建立整体地图；
3. 一次只学一个编号章节；
4. 每个核心概念停下来回答：它是什么、怎么工作、边界是什么、游戏里怎么用；
5. 做本章少量高信息量题；
6. 需要动手验证时再做微实验，不为了完成形式而写报告。

“能解释机制并通过一个反例或实验验证”比“页面全部看完并打勾”更重要。

## 四、如何做题和查看答案

每门课程包含：

```text
assessments/questions.md     # 少而精的题目
assessments/answers.md       # 折叠的最小提示、答案和详细解析
assessments/rubric.md        # 判断回答是否真正到位
```

推荐流程：

1. 先在心里回答；复杂题只在纸上写关键词或草图；
2. 没思路时只展开对应的“最小提示”；
3. 形成答案后再展开完整解析；
4. 对照结论、机制、边界、常见错误和游戏映射；
5. 答错时立即合上解析，用自己的话重新回答一次。

不强制建立个人作答文档或错题本。只有某个错误反复出现时，才按自己的习惯记录。

## 五、如何做实践

公开课程中的：

```text
labs/README.md       # 实验目标、约束、起始材料和验收标准
labs/solutions.md    # 折叠提示、参考路线、验证和常见失败
```

实践四步法：

1. 只读 `labs/README.md`，在自己习惯的位置实现；
2. 卡住 20–30 分钟后，只展开 `labs/solutions.md` 的最小提示；
3. 先让自己的实现通过验收，再查看完整参考路线；
4. 比较差异，不要用参考代码直接覆盖自己的实现。

如果想把个人代码放在本仓库中，按需创建 `.practice/<course-slug>/`。它已被 Git 忽略，不会影响公开教程。

### 无引擎实践

用于 C/C++、数据结构、算法、操作系统、网络和工具课程。保留最少但关键的证据：构建命令、固定输入输出、测试和失败案例。不为了“像游戏”而强行启动引擎。

### Unity 实践

用于战斗手感、肉鸽玩法、UI、资源和快速内容迭代：

- 使用单独测试场景和占位素材；
- 随机逻辑支持种子复现；
- 测试帧率变化和固定时间步；
- 规则、表现、输入和 UI 尽量分离；
- 不提交 `Library/`、`Temp/`、`Build/`。

### Unreal Engine 实践

完成对应的 Unity 或无引擎概念后，再用 UE C++/蓝图重建一个关键系统。重点记录在代码和结构本身：Gameplay Framework 职责、生命周期、网络角色、C++/蓝图/Data Asset 边界。不提交 `Binaries/`、`Intermediate/`、`Saved/`。

## 六、一次高效学习会话

推荐 60–120 分钟：

```text
5 分钟   网站自动回到上次位置，快速回忆
25 分钟  学一个核心主题并自己解释
15 分钟  心答/纸答 2–4 道高价值题
30 分钟  做一个最小实验或验证反例
10 分钟  对照答案与参考解法，修正理解
```

时间不足时，优先保留“解释机制 + 做题校验 + 最小验证”，删除抄笔记和形式化报告。

## 七、怎样算学会

不要求填写完成表。进入下一主题前，快速判断自己是否能：

- 不看资料解释核心机制和边界；
- 预测一个反例或错误代码会发生什么；
- 说出它在游戏系统中的实际用途；
- 必要时写出最小实现并通过验收。

如果四项大致都能做到，就继续；做不到就回看对应小节或做一个微实验，不需要额外维护学习档案。
