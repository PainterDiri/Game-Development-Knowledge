# C 程序设计课程地图（先读这里）

这不是术语目录，而是一条可验证的依赖链。每一章都必须留下一个可以运行、测量或解释的产物；如果只“看懂”而没有完成证据，就不要把它当作已经掌握。

## 前置诊断

运行：

```bash
cc --version
printf '#include <stdio.h>\nint main(void) { puts("ok"); return 0; }\n' > /tmp/c-course.c
cc -std=c17 -Wall -Wextra -pedantic /tmp/c-course.c -o /tmp/c-course && /tmp/c-course
```

- 不会解释 `-std=c17`、`-Wall`、`-o`、`return 0`：从第 1 章开始；
- 能编译但不会解释变量和函数：从第 2 章开始；
- 已能独立写 `main`、数组循环和函数：先做第 9 章“指针三问”诊断，再回看前面；
- 已熟悉 C 但没有做过 Sanitizer：至少完整学习第 11、15、16、17 章。

## 概念出口图

```text
值在哪里？ → 类型和对象
谁改变它？ → 表达式、分支、函数
活多久？   → 作用域、存储期、所有权
能访问多大？ → 数组长度、字符串终止符、指针区间
谁负责释放？ → 动态内存契约
怎样证明？ → 警告、Sanitizer、测试、可重复输入
怎样进入引擎？ → 稳定 C ABI + 薄适配器
```

## 阅读节奏

每章先运行最小代码，再读机制解释；然后故意改坏一处，观察编译器或测试如何暴露它；最后用“游戏映射”把概念翻译成运行时问题。章节中的代码片段是教学用最小复现，完整可编译基线在 `code/runtime-kit/`。

## 章节依赖与完成标准

- 1–6：程序、值、控制流和模块边界；完成后应能写多文件命令行程序；
- 7–10：连续内存、字符串、指针和输出参数；完成后应能为数组 API 写清 `pointer + length` 契约；
- 11–14：所有权、布局、位表示和文件输入；完成后应能处理失败，不把坏数据当成合法状态；
- 15–18：诊断、测试、组件化和引擎接缝；完成后应能交付并解释一个 C 运行时组件。

每章结尾的“下一章连接”是硬依赖，不是可有可无的总结。最后用 [主实践](../practice.md) 做一次从代码、测试到接缝契约的闭环。
