# 8. 字符串与输入解析：读到几个数字，不等于读懂一条命令

第 7 章给了数组的长度和容量。本章把数组放到一个不能控制输入的边界上：玩家输入 `wave 3x`，程序应该生成三个敌人，还是拒绝整条命令？答案取决于协议；本课约定只接受完整命令，所以必须拒绝。只看到转换函数返回 3 就执行，会把错误文本变成合法状态变化。

本章出口是：能区分字节、字符串、整行与命令；能写一个范围受控的整数解析函数；能解释坏输入如何被拒绝，以及下一行为什么仍可继续执行。这里的游戏映射是控制台、配置导入与服务端入口共同具有的输入边界，不要求先会网络编程。

## 8.1 字符数组何时才是字符串

下面是依赖 `<stdio.h>` 的片段，不是完整程序：

```c
char name[8] = "Isaac";
printf("%s\n", name);
```

数组的 8 个元素为 `I s a a c \0 \0 \0`。前五个是名字，第一处 `\0` 是值为零的字符，标记字符串结束；它不是数字字符 `'0'`。`%s` 不接收数组容量，而是不断读到终止符。所以 `char name[5] = {'I','s','a','a','c'};` 虽然是合法字符数组，却不能交给 `%s` 当作字符串，否则会读出对象边界，属于未定义行为。

区分三个量：

| 量 | `name` 的例子 | 用途 |
|---|---:|---|
| 容量 `sizeof name` | 8 个 C 字节 | 写入前证明空间足够 |
| 字符串长度 `strlen(name)` | 5 | 已知有终止符后，数终止符前的字节 |
| 终止符占用 | 1 | 存放长度为 5 的字符串至少需要容量 6 |

`strlen` 在 `<string.h>` 中声明，返回 `size_t`。它没有容量参数，不能用来检查一个任意缓冲区是否安全：调用之前就必须知道对象中存在可访问的终止符。`sizeof` 在指针参数上也不会还原数组容量。

“字节数”不是“用户看到的字数”。C 的 `sizeof(char)` 定义为 1，但每字节位数由 `CHAR_BIT` 指定；本实践目标是常见的 8 位字节平台。UTF-8 中文字符常占多个字节，组合字符还可能由多个码点组成；本章只设计 ASCII 命令词和数字，不实现 Unicode 文本编辑。后续资源与 UI 课程再处理文本编码与显示边界。

## 8.2 先补一个输出参数模型

下一节需要 `char *end` 和 `&value`，不能等到指针章节才知道它们在这里做什么：

```c
int health = 100;
int *location = &health;
*location = 42;
```

这是依赖外层函数的片段。`health` 是存整数的对象；`&health` 取得这个对象的地址；`location` 是存地址的指针变量；`*location = 42` 沿地址写回原对象，因此最后 `health` 为 42。这里 `*` 在声明中表示指针类型，在表达式中表示通过地址访问对象，不是乘法。

函数返回 `bool` 可以表达成功/失败，再通过 `int *out` 输出整数。调用时传 `&health`，函数成功时写 `*out`，失败时不写。这样不会用一个特殊整数同时表示合法数据和错误。`NULL` 表示空指针，不指向可供访问的对象，不能解引用。完整的指针运算、`const` 和生命周期规则在第 9 章展开；这里的地址只在函数调用期间借用。

## 8.3 数字转换必须同时回答四个问题

`atoi` 不适合作为受控输入的基础：合法的 `"0"` 与没有数字的 `"bad"` 都可能得到 0，且不可表示的结果没有可依赖的溢出恢复契约。不要拿超大数字运行 `atoi`，然后把观察到的值当成标准规定。

`strtol` 在 `<stdlib.h>` 声明。这里用十进制：

```c
long value = strtol(text, &end, 10);
```

- `text` 指向输入字符串；
- `end` 是一个 `char *` 变量，`&end` 让函数能把“停止解析的位置”写进它；这解释了为什么传的不是 `end`；
- `10` 指定进制；
- 返回类型为 `long`，不能还没检查就转成范围可能更小的 `int`。

必须逐项检查：有没有读到数字？转换是否超出 `long`？结果是否超出业务范围？停止位置之后是不是协议允许的内容？转换函数会接受数字前的空白及正负号，这不一定是你想要的语法，协议需要额外限制。

### 完整程序：只接受 0 到 1000 的十进制生命值

保存为个人临时目录的 `parse_health.c`。这不是“任意整数解析器”：语法为至少一位数字，可有前导零，不接受符号、空白或尾随字符。

```c
#include <errno.h>
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>

static bool parse_health(const char *text, int *out) {
    if (text == NULL || out == NULL) return false;
    if (*text < '0' || *text > '9') return false;
    errno = 0;
    char *end = NULL;
    long candidate = strtol(text, &end, 10);
    if (end == text || errno == ERANGE || *end != '\0') return false;
    if (candidate < 0 || candidate > 1000) return false;
    *out = (int)candidate;
    return true;
}

int main(void) {
    const char *cases[] = {"42", "0", "1000", "1001", "42x", "-1", "", "999999999999999999999999999999999999999999"};
    for (size_t i = 0; i < sizeof cases / sizeof cases[0]; ++i) {
        int health = 77;
        bool is_ok = parse_health(cases[i], &health);
        printf("case=%zu ok=%d health=%d\n", i, is_ok ? 1 : 0, health);
    }
    return 0;
}
```

```bash
cc -std=c17 -Wall -Wextra -Wconversion -pedantic parse_health.c -o parse_health
./parse_health
```

预期前 3 行成功，生命值分别为 42、0、1000；后 5 行均为 `ok=0 health=77`。不同平台的 `long` 上限可能不同，不用“某个固定 11 位数字必然溢出 long”作为可移植假设；无论转换层是否超界，本函数还必须执行 1000 的业务上限检查。

逐步看 `"42x"`：首字符是数字 → 转换得到 42 → `end` 指向 `x` → 不是终止符 → 返回失败 → 从未执行 `*out = ...` → 原生命值 77 保留。把尾部检查故意删掉再运行，case 4 会错误成功；恢复检查后必须重新通过。这就是失败原子性：错误不会留下半更新结果。

`errno` 是库提供的错误状态。调用前清零，是为了不把以前留下的错误误认成本次错误；这里检查 `ERANGE` 表示结果超出转换类型范围。成功的数值 0 不能单独证明成功，`end` 和范围检查仍然必需。

## 8.4 读入一段，不等于读到整行

`fgets` 最多在缓冲区写入容量减一的字符，并在成功时补终止符；若读到换行，会保留 `\n`。返回 `NULL` 时需要用 `feof`/`ferror` 区分正常输入结束与读取错误。下面仅展示读取片段：

```c
char line[8];
if (fgets(line, sizeof line, stdin) != NULL) {
    /* 先判断是否得到完整的一行，再解析。 */
}
```

容量 8 只能放 7 个数据字符加终止符：

| 输入 | 首次读取 | 不能草率下的结论 |
|---|---|---|
| `wave 2` 加换行 | 6 字符和换行，再补零 | 这是完整行 |
| `1234567` 加换行 | 7 字符，换行仍留在流中 | 没有换行不等于超长；需再读一个字节判定 |
| `wave 2` 加 200 个空格再换行 | 仅一个前缀 | 不能执行前缀后把剩余内容当新命令 |
| `quit` 后 EOF | 4 字符，没有换行 | 文件最后一行允许不带换行 |

若协议拒绝超长行，应一直读到换行或 EOF 才恢复边界。只“再调用一次 fgets”不够，因为坏行可以比两个缓冲区还长。丢弃时用 `int byte = fgetc(...)`，因为返回值还要表示不同于有效字节的 `EOF`。

本实践的 `rg_read_line` 采用逐字节读取：最多保存 127 个数据字节；发现第 128 个或嵌入的 NUL 就把整行判为非法，但继续消费到换行/EOF。返回结果区分成功、正常结束、非法行和 I/O 错误。NUL 必须拒绝，否则字符串函数会只看见 `wave 2\0hidden` 的前缀。该读取器是教学规模实现，不声称适合高吞吐网络 I/O。

## 8.5 从完整行到候选命令，再到领域状态

主实践有三层，各自负责不同失败：

```text
输入流 → rg_read_line：保证物理行边界，无 NUL，不超容量
字符串 → rg_parse_command：检查命令全名、参数数量、数字语法和类型范围
候选命令 → rg_runtime_*：检查容量、索引、游戏是否结束，再修改状态
```

`wave 33` 语法正确且可表示为 `size_t`，但运行时容量 32，所以由领域层拒绝；`wave 3x` 在语法层失败，运行时根本不应被调用。`statusx` 不是 `status`，不能用只比较前六字节的 `strncmp` 接受。`hit 0 1 extra` 参数多了一个，也必须拒绝。

参考实现 `rg_cli.c` 使用本地字符数组拆出最多三个词，数字用 `strtoumax` 转成标准提供的最宽无符号整数类型 `uintmax_t`，再检查目标上限 `SIZE_MAX`、`INT_MAX` 或 `UINT32_MAX`。声明在 `<inttypes.h>`。由于无符号转换也可能接受负号，首字符数字检查仍然必要。这里选择拒绝 `+1`，不是声称语言转换函数不支持它。

解析成功后才把局部 `RgCommand candidate` 赋给输出；结构体和枚举的完整语法在第 10 章展开。现在只需理解它是包含“命令种类、数量、索引、伤害”的候选记录。解析器没有运行时指针，所以不能偷偷扣血或生成敌人。

不能使用 `sscanf(..., "%d", ...)` 对任意大数字做可靠范围验证：成功匹配数量不证明目标对象能够表示转换结果；超出可表示范围有未定义行为风险。参考实现不能以“只是教学程序”为由违反正文的输入契约。

## 8.6 在同一个主实践中验证恢复

按[主实践](../practice.md)初始化个人副本后，在 `runtime-kit` 中运行：

```bash
make test
printf 'wave 3x\nstatus\nwave 1\nstatus\nquit\n' | ./arena --seed 42
```

第一条输出 `invalid command`；第一次 `status` 与启动时相同；`wave 1` 成功；最后状态为 `wave=1 player_hp=40 enemies=1`。比较完整字段，checksum 只是便于定位的摘要，不是无碰撞证明。

`test_cli.c` 测数字边界与行读取；`test_arena.py` 从真实可执行入口输入坏行，检查拒绝后状态不变，以及下一条合法命令成功。单独测试 `parse_health` 不能证明主程序确实调用了它，因此需要这层集成测试。

## 本章练习

### C08-Q1：转换成功在哪一步被否决

沿本章 `parse_health` 的代码，分别追踪 `"0007"`、`" 7"`、`"7x"`、`"1001"`。每次从 `health=77` 开始，给出第一个拒绝点或成功点，以及最终生命值。不能只说“格式不对”。

<details><summary>讲解与验证</summary>

`0007` 首字符是数字，转换得到 7，尾部为空且范围合法，末尾写回 7。` 7` 在首字符检查失败；本协议拒绝空白，即使 `strtol` 本身可以跳过它。`7x` 转换得到 7，但 `end` 指向 `x`，在尾部检查失败。`1001` 转换和尾部都正确，在业务上限检查失败。后三种均未写输出，生命值保持 77。

常见错误是以转换出的值判断成功，或把转换函数支持的全部语法当成业务协议。把四项加入程序验证，注意不要先把 `health` 清零。游戏映射：服务端或工具的输入层应在承诺的语法内工作，不默默“修好”含糊输入。
</details>

### C08-Q2：一条坏行会不会变成两条好命令

读取器数据容量为 127 字节。输入是 `wave 2`、随后 130 个空格、然后 `wave 1`，最后才出现换行；下一行是 `status`。预期生成几只敌人？若代码每读到一个缓冲区就立即解析，会出什么问题？再说明恰好 127 字节后 EOF 应如何分类。

<details><summary>讲解与验证</summary>

整条物理行超过限额，必须拒绝，所以生成 0 只；读取器继续消费到换行，下一行 `status` 正常执行。错误实现可能先执行 `wave 2`，随后把同一行剩余的 `wave 1` 当另一条命令，总共生成 3 只。这不是“少检查了空格”，而是丢失了协议的行边界。

恰好 127 字节后 EOF 未超过数据容量，可以把它作为完整最后一行交给语法层；不保证语法层接受。第 128 字节才构成超长。边界测试包含 126/127/128、换行与 EOF、多个缓冲区长度、NUL；参考 `test_line_boundaries` 使用更小容量验证同一机制。游戏映射：控制台和流式协议都不能把截断片段当完整消息。
</details>

### C08-Q3：把拒绝发生的位置分清

容量 32、当前敌人数 0、玩家存活时，判断 `wave 33`、`wave -1`、`hit 0 1`、`statusx` 各由读取层、语法层还是领域层拒绝。用哪些观察区分“没执行”与“执行后刚好还是原样”？

<details><summary>讲解与验证</summary>

四条短文本都能通过读取层。`wave 33` 通过语法层，在领域层因容量不足拒绝；`wave -1` 在语法层拒绝符号；`hit 0 1` 通过语法层，在领域层因当前没有索引 0 的敌人拒绝；`statusx` 不等于命令全名，在语法层拒绝。

检查解析返回值、领域错误码和状态前后字段；在模块测试中，语法层失败时输出候选也保持哨兵值。只看敌人数不变不能区分阶段，错误实现可能消耗 RNG 后又撤销数量。因此还要比较 RNG、波次、生命等语义字段。这里不要求网络库或线程知识；迁移到服务器时同样先解析再执行权威规则，拒绝不等于断开整个会话。
</details>
