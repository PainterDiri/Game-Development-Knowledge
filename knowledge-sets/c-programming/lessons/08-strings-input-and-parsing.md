# 8. 字符串、字节、输入与解析：文本边界必须显式

命令行房间模拟器要读 `wave 3`、`hit 0 10`。文本输入的问题不在于“会不会调用 scanf”，而在于输入长度、终止符、非法字符、溢出和错误恢复。C 字符串是以 `\0` 终止的字符数组，不是带长度的安全对象。

## 机制

本章把可观察现象还原为语言机制和不变量，而不是只记 API 名称。

## 8.1 字节与终止符

```c
char name[8] = "Isaac";
printf("%s\n", name);
```

初始化字符串包含结尾的 `\0`，数组至少需要 6 个字节。若输入恰好填满缓冲区，必须为终止符额外留空间。`strlen` 在遇到 `\0` 前逐字节扫描，前提是传入对象确实以 `\0` 终止；对任意二进制数据使用它是错误。

## 8.2 为什么优先 `fgets`

```c
char line[128];
if (fgets(line, sizeof line, stdin) == NULL) {
    /* EOF 或读取错误 */
}
```

`fgets` 最多读 `sizeof line - 1` 个字符，并在成功时补 `\0`；若一行太长，换行符不会被读入，需要继续丢弃剩余字符或拒绝该行。`scanf("%s", ...)` 若没有宽度限制可能写越界；混用格式化输入还容易留下换行符。

## 8.3 解析是验证，不是转换捷径

`atoi` 无法区分输入 0 与转换失败，也不提供溢出诊断。更稳妥的整数解析路径使用 `strtol`：检查 `errno`、结束指针是否到达允许的尾部、结果是否在业务范围内，再转换为 `size_t` 或 `uint32_t`。解析层只返回结构化命令，不直接修改运行时状态。

```text
读整行 → 语法拆分 → 范围检查 → 生成 Command → 运行时执行
```

这样可测试“非法输入不改变状态”。

## 8.4 故意失败、恢复与游戏映射

测试空行、过长行、`wave -1`、`wave 3x`、超大数字、未知命令和 EOF。错误消息应包含下一步，不要让一次坏行终止整个工具（除非协议规定）。游戏工具、控制台和存档读取都需要同样的“字节 → 语法 → 类型化命令 → 领域规则”分层。

## 进一步拆解与实验

## 8.5 可运行的整数解析

`fgets` 解决“读取不会越过缓冲区”的一部分问题，但它不会验证文本是否是合法整数。用 `strtol` 解析时，要同时检查错误码、结束位置和范围：

```c
#include <errno.h>
#include <limits.h>
#include <stdbool.h>
#include <stdlib.h>

bool parse_int(const char *text, int *out) {
    if (text == NULL || out == NULL) return false;
    errno = 0;
    char *end = NULL;
    long value = strtol(text, &end, 10);
    if (end == text || errno == ERANGE || value < INT_MIN || value > INT_MAX) {
        return false;
    }
    while (*end == ' ' || *end == '\t' || *end == '\n') ++end;
    if (*end != '\0') return false;
    *out = (int)value;
    return true;
}
```

输入 `"42\n"` 成功，`"42abc\n"` 失败，空字符串、超大数字和负数是否允许由调用者的业务范围决定。函数只在全部检查成功后写 `*out`，这样失败时输出参数保持原值，调用者不会把“半解析结果”当成有效状态。

## 8.6 缓冲区边界的三个长度

处理文本时区分：容量（数组能放多少字节）、当前长度（不含 `\0` 的字符数）和已读取字节数。C 字符串的终止符也占一个字节：容纳最多 7 个可见字符的数组至少要有 8 个元素。

```c
char command[16];
if (fgets(command, sizeof command, stdin) == NULL) {
    /* EOF 或读取错误 */
}
```

若一行过长，`fgets` 只读取前缀，换行符不会出现。程序必须选择：丢弃这一行剩余部分并报错，或支持继续拼接；不能把前缀静默当成完整命令。可用第二次 `fgets` 清空到换行，但要记录这是恢复输入边界，不是“多读一次就安全”。

## 8.7 文本协议与 CLI 状态机

把命令解析分成三层：读取一行、识别命令词、解析参数并校验业务范围。这样 `wave 3` 的词法错误、参数格式错误和“波次数量超过上限”可以分别诊断。解析层不应直接修改运行时；先得到候选命令，再让规则层验证并提交状态，失败时保持原状态。

故意失败实验：把 `atoi` 换成输入 `"wave nope"`、`"wave 999999999999999999999"` 和一行超长字符串，比较它只返回 0 与 `strtol` 能提供的错误信息。游戏里的控制台、存档导入和调试命令都需要同样的“输入文本 → 候选值 → 业务校验 → 状态提交”边界。

### C08-Q1：为什么 `atoi` 不够

说明 `atoi("0")` 和 `atoi("bad")` 的歧义，并列出 `strtol` 至少要检查的三个结果。

<details><summary>最小提示</summary>

需要区分没有数字、数字后有垃圾和数值超界。
</details>

<details><summary>讲解与验证</summary>

`atoi` 失败通常返回 0，因此与合法 0 无法区分。`strtol` 后应检查 `errno == ERANGE`、`end != start`、`*end` 是否是允许的空白/行尾，并检查结果落在业务上下限。再进行有符号到无符号转换。测试 `0`、`bad`、`3x`、负数和极大数。游戏映射：seed、伤害和关卡索引不能让非法文本悄悄变成合法大整数。
</details>

### C08-Q2：处理截断输入

缓冲区只能存 8 个字符，用户输入 20 个字符。你如何判断并恢复下一次读取？

<details><summary>最小提示</summary>

观察是否读到换行符；没有则继续读取直到换行或 EOF。
</details>

<details><summary>讲解与验证</summary>

若 `fgets` 成功但缓冲区中没有 `\n` 且未到 EOF，说明本行被截断；应把剩余字符读掉，报告“行过长”，不要把尾巴当下一条命令。边界是刚好填满、刚好含换行和 EOF 无换行。用重定向文件重复测试。游戏映射：控制台命令和网络文本协议若不同步，下一条命令会被错误拼接。
</details>
