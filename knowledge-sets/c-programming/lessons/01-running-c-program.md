# 1. 从源码到进程：第一段 C 程序究竟经历了什么

你在编辑器里写下 `printf("hello\n");`，文件仍只是文本。它不能自己占用 CPU、读取输入或产生退出码。本章先把“写代码”“生成程序”“运行进程”分开，因为以后遇到错误时，第一步永远是判断失败发生在哪一阶段。

## 机制

本章把可观察现象还原为语言机制和不变量，而不是只记 API 名称。

## 1.1 最小程序与可观察结果

```c
#include <stdio.h>

int main(void) {
    puts("arena ready");
    return 0;
}
```

把它保存为 `hello.c`，在临时目录运行：

```bash
cc -std=c17 -Wall -Wextra -Wpedantic hello.c -o hello
./hello
echo $?
```

第一条命令读取 `hello.c`，经过预处理、编译、汇编和链接，生成可执行文件 `hello`；第二条启动一个进程；第三条读取上一进程的退出状态。预期先看到 `arena ready`，再看到 `0`。`0` 通常表示成功，非零值表示调用者可以自动判断的失败类别。

## 1.2 四个翻译阶段不是一句“编译”

1. **预处理**处理 `#include`、条件编译和宏，产生送给编译器的记号流；
2. **编译**检查语法与类型，把每个翻译单元变成汇编或中间表示；
3. **汇编**生成目标文件，其中已有机器码和未解析符号；
4. **链接**把目标文件与库组合，解析 `puts` 等外部符号，生成可执行文件。

可故意制造三类失败：删掉分号得到编译错误；声明但不定义 `apply_damage` 得到链接错误；编译成功后访问非法内存才是运行时失败。错误阶段不同，修复工具也不同。不要看到红字就随机改代码。

```bash
cc -std=c17 -E hello.c > hello.i   # 只预处理
cc -std=c17 -S hello.c -o hello.s  # 到汇编
cc -std=c17 -c hello.c -o hello.o  # 到目标文件
cc hello.o -o hello                # 单独链接
```

`-Wall -Wextra -Wpedantic` 不是“保证程序正确”，而是让编译器暴露更多可疑代码；警告应被阅读、理解并修复，而不是一律关闭。

## 1.3 标准输入、标准输出与标准错误

每个命令行进程通常有三条流：`stdin` 输入、`stdout` 正常结果、`stderr` 诊断。它们可以分别重定向：

```bash
./hello > run.txt 2> error.txt
```

游戏构建工具也应把机器可消费结果与人类诊断分开；否则 CI 无法稳定解析输出。`puts` 自动附加换行，`printf` 则按格式串组合值。第一次使用格式化输出时必须让格式说明符与参数类型匹配，类型不匹配可能产生未定义行为。

## 1.4 `main` 的参数与退出契约

```c
int main(int argc, char **argv) {
    if (argc != 2) {
        fprintf(stderr, "usage: %s <seed>\n", argv[0]);
        return 2;
    }
    printf("seed text = %s\n", argv[1]);
    return 0;
}
```

`argc` 是参数数量，`argv` 是指向参数字符串的指针数组；`argv[0]` 通常是程序名。这里只打印 seed 文本，还没有把它安全转换成整数。错误用 `stderr`，并返回非零退出码，使测试脚本能区分“正常输出”和“用法错误”。

## 1.5 验证、失败与游戏映射

验证时同时记录命令、退出码和产物：

```bash
./hello 42 >out.txt 2>err.txt; printf 'exit=%d\n' "$?"
./hello >out.txt 2>err.txt; printf 'exit=%d\n' "$?"
```

预期第一条成功，第二条输出用法并失败。常见错误是双击程序后窗口消失便认为“C 没运行”，或者把链接错误误当函数运行时找不到。游戏映射：资源转换器、服务器、打包器和离线验证器都依赖稳定的命令行、标准流和退出码契约。

## 进一步拆解与实验

## 1.6 一次构建命令的逐段解释

把下面命令拆开看，而不是把它当成一个黑盒：

```bash
cc -std=c17 -Wall -Wextra -Wpedantic hello.c -o hello
```

- `cc` 是编译器驱动程序。它通常会替你调用预处理器、编译器、汇编器和链接器；它不是 C 语言本身。
- `-std=c17` 选择语言方言。没有它时，编译器可能接受某些扩展，导致“本机能编译、另一台机器不能编译”。
- `-Wall`、`-Wextra`、`-Wpedantic` 请求一组额外诊断。它们提高发现问题的概率，但不是证明器；每条警告都要理解成一个待调查的假设。
- `hello.c` 是输入源文件。命令不会修改它。
- `-o hello` 指定输出文件。如果省略，许多 Unix 编译器会默认生成 `a.out`，这只是默认文件名，不是语言规则。

可以用 `echo $?` 观察驱动程序的退出码。编译失败时不要运行旧的 `hello`，因为旧产物可能仍然存在，让你误以为新代码已经生效。更安全的做法是先删除临时输出，或把构建输出放进单独目录。

## 1.7 从源文件到进程的时间线

```text
hello.c --预处理--> hello.i --编译--> hello.s --汇编--> hello.o
                                                   \
                                                    --链接 + 库--> hello
hello --操作系统加载--> 进程地址空间 --执行 main--> stdout/stderr + 退出状态
```

这里有三个容易混淆的“东西”：源文件是可编辑输入，目标文件是尚未完成外部符号解析的中间产物，可执行文件才是操作系统可以装载的入口。进程不是文件的别名；进程拥有自己的栈、堆、寄存器和打开的文件流。

验证每一步：

```bash
cc -std=c17 -E hello.c -o hello.i
cc -std=c17 -S hello.c -o hello.s
cc -std=c17 -c hello.c -o hello.o
nm hello.o | grep ' U '
cc hello.o -o hello
file hello
```

`nm` 和 `file` 是观察工具，不是程序运行所必需的。不同平台的输出格式会不同，重要的是理解：目标文件可能仍有 `U`（未定义、等待链接）符号，而最终可执行文件需要这些符号被解析。

## 1.8 输入、输出和退出码的契约

一个可测试的命令行程序要先定义契约，再写实现：

| 情况 | stdout | stderr | 退出码 |
|---|---|---|---:|
| 参数正确 | 正常结果 | 空 | 0 |
| 参数数量错误 | 空 | 用法提示 | 2 |
| 输入内容非法 | 空或部分结果（需明确） | 具体诊断 | 3 |
| 内部失败 | 空 | 可定位的错误 | 1 |

退出码不是给人看的长错误信息，它是调用者的简短协议；错误文本用于诊断，退出码用于脚本分支。若程序同时打印正常结果和错误信息，测试应分别捕获两条流，而不是把终端上混在一起的文字当成唯一证据。

把输入写成“最小可复现样例”也属于编程能力。例如先用 `printf` 管道提供固定输入，再保存 seed 和参数；不要让示例依赖交互时的手工输入速度。

## 本章练习

### C01-Q1：错误发生在哪一阶段

`cc main.c -o arena` 报告 `undefined reference to rg_spawn_wave`。说明阶段、最可能原因和验证步骤。

<details><summary>最小提示</summary>

声明让编译器知道函数形状，定义才给链接器机器码。
</details>

<details><summary>讲解与验证</summary>

这是链接失败，常见原因是实现文件未进入命令，或定义名/链接属性不一致。先分别执行 `cc -c main.c` 与 `cc -c runtime.c`，再用 `cc main.o runtime.o -o arena`。若前两步通过而最后一步成功，就证明缺少链接输入。常见错误是在头文件复制普通函数定义，继而造成多重定义。游戏映射：原生插件和平台库同样要区分头文件可见与二进制已链接。
</details>

### C01-Q2：设计可脚本化的失败

为“缺少 seed 参数”设计 stdout、stderr 和退出码，并说明怎样自动验证。

<details><summary>最小提示</summary>

正常结果与诊断分流，脚本同时断言文本和 `$?`。
</details>

<details><summary>讲解与验证</summary>

把用法写入 `stderr`，不产生正常结果，返回约定的非零码（例如 2）。运行 `./arena >out 2>err; test $? -eq 2; test ! -s out; grep -q usage err`。边界是退出码空间有限，详细错误仍需文本或结构化报告。常见错误是打印错误却返回 0，导致 CI 把失败当成功。游戏映射：构建和内容校验器必须能被流水线可靠判定。
</details>
