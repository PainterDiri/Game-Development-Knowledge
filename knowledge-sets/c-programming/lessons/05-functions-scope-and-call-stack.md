# 5. 函数、作用域与调用栈：参数默认是传值

上一章能写正确循环，但把所有逻辑塞进 `main` 会让状态边界消失。函数是“输入 → 结果/副作用”的命名边界；理解它还要回答一个初学者常问的问题：为什么在函数里改一个 `int`，调用者的变量没有变？

## 传值实验

```c
#include <stdio.h>

void try_change(int value) { value = 99; }

int main(void) {
    int health = 10;
    try_change(health);
    printf("health=%d\n", health); // 仍是 10
}
```

调用函数时，参数对象得到实参值的副本。函数中的 `value` 是另一个对象；这不是“引用失效”，而是 C 的参数传递模型。局部对象通常具有自动存储期：进入函数块时存在，离开块时生命周期结束。

## 返回值与副作用

优先把普通计算写成返回值：

```c
int clamp_health(int health, int max_health) {
    if (health < 0) return 0;
    if (health > max_health) return max_health;
    return health;
}
```

这样测试只需比较返回值；需要修改调用者状态时，下一章会使用指针参数。函数契约应写清：输入允许范围、返回值含义、是否修改参数、是否分配内存、失败如何表示。

## 作用域与遮蔽

```c
int damage = 3;
if (damage > 0) {
    int health = 10;
    int damage = 4; // 遮蔽外层 damage，容易误读
    health -= damage;
}
```

内层名字可以遮蔽外层名字，但这不是好的状态管理。使用 `-Wshadow`，让编译器把“看起来合法但可维护性差”的错误暴露出来。

## 调用栈的边界

调用 `clamp_health` 时，参数和局部对象需要一个当前调用上下文；函数返回后，这些自动对象不能再被使用。不要返回局部数组的地址：它指向已结束生命周期的对象。这个错误可能“在开发机上打印正常”，仍是未定义行为。
