> **这门课解决什么问题？** 当游戏中的“移动一帧”“生成一波敌人”“读取一个存档字段”偶尔崩溃、越界或在另一台机器上表现不同，不能只靠“多加一个 `if`”修补。你需要能从值、地址、对象生命周期、数据布局、错误路径和编译器诊断解释它为什么正确或失效。

## 适合谁与前置检查

默认面对第一次系统学习编程的人。前置只有已完成的[工具链与 Git](../toolchain-and-git/README.md)：会打开终端、运行命令、阅读退出码、用 Git 保存小步修改。若还不熟，先完成下面的 10 分钟补桥：

```bash
mkdir -p c-bridge && cd c-bridge
printf '#include <stdio.h>\nint main(void) { puts("ready"); return 0; }\n' > main.c
cc -std=c17 -Wall -Wextra -pedantic main.c -o hello && ./hello
printf 'exit=%s\n' "$?"
```

能解释“源文件被编译成可执行文件、`./hello` 创建一个进程、`return 0` 表示成功”即可继续；不必先会指针。

## 课程地图：从可观察失败到可交付组件

这门课刻意把最容易跳步的 C 难点拆开：表达式和控制流先建立可预测的值变化；函数和多文件先建立边界；数组、字符串、指针、动态内存再逐层回答“这块内存是谁的、活多久、能访问多大”。最后才把这些规则组合成一个不依赖引擎的运行时组件库。

```mermaid
graph LR
    A[运行与退出码] --> B[类型与值]
    B --> C[表达式与转换]
    C --> D[分支与循环不变量]
    D --> E[函数、作用域、调用栈]
    E --> F[头文件、链接与模块]
    F --> G[数组与连续内存]
    G --> H[字符串与字节]
    H --> I[指针、const、别名]
    I --> J[输出参数与迭代器边界]
    J --> K[动态内存与所有权]
    K --> L[结构体、布局、对齐]
    L --> M[枚举、联合、位标志]
    M --> N[文件 I/O 与错误模型]
    N --> O[未定义行为、Sanitizer、调试]
    O --> P[测试、不变量、基准]
    P --> Q[组件 API 与 C ABI]
    Q --> R[Unity/UE 适配与回滚]
```

| 3 | 类型模型 → 整数、浮点、转换与溢出边界 | 编译器警告 + 边界测试 | 控制流依赖布尔条件 |
| 4 | 值变化 → 分支、循环与不变量 | 计数器/累加器测试 | 复杂逻辑需拆进函数 |
| 5 | 循环逻辑 → 函数、作用域、调用栈 | 参数传值实验 | 多文件需要声明和链接 |
| 6 | 函数 → 头文件、定义、链接和 API 边界 | 两个 `.c` 文件构建 | 数组 API 要表达长度 |

| 8 | 数组 → C 字符串、缓冲区与编码边界 | 安全拷贝/格式化 | 需要用地址传递大对象 |
| 9 | 数组边界 → 指针、`const`、别名规则 | 指针追踪图 | 输出参数和迭代器需明确契约 |
| 10 | 指针模型 → 指针参数、区间和回调 | `min/max` 与范围函数 | 持久状态需要所有权 |
| 11 | 所有权问题 → `malloc/free`、失败与生命周期 | ASan 修复 use-after-free | 结构体封装状态与布局 |
| 12 | 动态状态 → 结构体、对齐、序列化尺寸 | `sizeof`/`offsetof` 测量 | 位表示用于紧凑状态 |

| 14 | 字节/状态 → 文件读写、错误码、恢复 | 损坏输入拒绝测试 | 诊断工具定位错误 |
| 15 | 失败样本 → UB、警告、Sanitizer、调试器 | ASan/UBSan 报告 | 测试把规则固化 |

## 适用版本与实验环境

- 正文以 **C17 可移植核心**为主，示例使用 `cc -std=c17 -Wall -Wextra -Wconversion -Wshadow -pedantic`；C23 已在 2024 年成为 ISO C 的新版本，但不同编译器/标准库的支持仍可能不同，因此只在“迁移注记”中提示，不把 C23 专属语法当作前置。
- 研究依据包括 ISO C11 免费公开草案 N1570 的对象、表达式、数组、函数、预处理器和库条款；它不是最新 ISO 规范的替代品，正文对版本敏感的结论会标注限制。
- 本机可用 Apple Clang 21；GCC、Clang 或 MSVC 均可完成核心实验。Windows 学习者可把 `cc` 换成 `clang`，或使用 WSL；命令差异不改变 C 的对象模型。
- Sanitizer 命令以 Clang/GCC 的 AddressSanitizer、UndefinedBehaviorSanitizer 为例；若平台不支持，先完成普通测试，再使用调试器或 Valgrind 等替代工具。

## 主实践、两个微实验与主项目接缝

- **主实践**：[固定容量房间/波次运行时组件库](practice.md)。独立实现 `Vec2`、确定性 RNG、敌人波次缓冲区和错误码 API；参考代码可编译、可测试、可用 seed 重现。
- **微实验 A**：故意制造栈对象逃逸、越界和 use-after-free，分别用编译器警告、ASan 和调试器解释报告。
- **微实验 B**：测量结构体字段顺序与位标志表示，比较可读性、`sizeof`、序列化稳定性和跨平台风险。
- **接缝**：`integrationMode=export`。C 代码只交付纯规则/数据组件和 `extern "C"` 边界，不直接依赖 Unity `GameObject`、UE `UObject`、渲染、输入或平台文件 API；Unity/UE 适配层拥有句柄生命周期，规则层拥有数据不变量。详见 [主项目接缝契约](integration-contract.md)。

## 学完后的可验证出口

你应能：

1. 从源文件、编译、链接、进程和退出码解释一次构建；
2. 用类型、转换、控制流和循环不变量解释结果，而不是靠试错；
3. 为数组、字符串和指针写出元素数、可写性、生命周期和所有权契约；
4. 识别未定义行为、实现定义行为和合法但危险的取舍，并用警告、Sanitizer、调试器和测试缩小问题；
5. 设计一个错误路径明确、状态所有者明确、可测试、可导出的 C 组件，并说明如何让 Unity/UE/C# 或 C++ 只通过薄适配层消费它。
