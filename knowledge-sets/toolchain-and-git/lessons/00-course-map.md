# 工具链与 Git · 课程地图

## 先回答一个工程问题

本课程不以“记住 Git 命令”或“会点 Unity/UE 菜单”为出口，而以一个可验收的承诺为中心：

> **另一台干净机器，拿到一个确定提交后，能否知道需要哪些工具、运行哪些命令、生成什么产物、测试是否通过，以及失败时如何定位？**

工具链（toolchain）是把源代码、资产、编译器/编辑器、脚本、测试、打包器和发布系统串起来的可执行路径；可复现工程（reproducible engineering）是让这条路径的输入、版本、配置、输出和证据都可被重建与比较。它不等于“所有平台产生完全相同的字节”。

## 前置检查

- **必需**：能在终端运行 Python 3.11+、Git 2.x，并理解文件、目录和进程的基本概念。
- **不要求**：先会 C/C#、Unity 或 Unreal；引擎部分只用来观察同一工程原则如何落地。
- **诊断题**：在没有打开 IDE 的情况下，写出一个小游戏从“修改源码”到“可交付构建”的 6 个输入/输出节点，并指出其中哪两个是缓存、哪两个必须进入版本控制。若不能区分“源文件”和“可再生目录”，先完成第 1 课的最小实验。

## 课程专属结构：沿一条交付链前进

工具链问题最容易被误解为命令清单；真正难点是跨边界追踪状态。因此课程按“输入如何流到证据”组织，而不是按 Git、Unity、CI 各写一章 API 介绍：

```mermaid
flowchart LR
    S[源代码/资产/配置] --> V[版本与依赖边界]
    V --> E[编辑/编译/打包环境]
    E --> T[测试与调试证据]
    T --> C[CI 与产物]
    C --> R[发布、回滚、复现]
    R -. 回归定位 .-> V
```

| 顺序 | 页面 | 必须形成的心智模型 | 主要验证 |
|---:|---|---|---|
| 1 | [从源到产物：工具链边界](01-source-to-artifact.md) | 源、配置、工具、缓存、产物和证据不是一类东西 | 干净目录构建、输入清单、Unity/UE 对照 |
| 2 | [Git：快照 DAG 与协作冲突](02-git-model-and-collaboration.md) | 提交是快照，分支是引用；合并解决语义冲突，不是魔法覆盖 | 分支、冲突、revert/bisect、LFS 取舍 |
| 3 | [可复现构建：锁定输入而非祈祷](03-reproducible-builds.md) | 版本、依赖、时间、路径、随机种子和平台都是构建输入 | manifest、两次构建、确定性测试 |
| 4 | [调试与回归：把失败变成证据](04-debugging-and-regression.md) | 可定位性来自最小复现、日志、符号、提交范围和故障分类 | seeded repro、bisect、断言、构建清单 |
| 5 | [CI、发布与回滚](05-ci-release-and-rollback.md) | CI 是可重复命令的执行器；缓存不是产物，绿色不是发布 | GitHub Actions、artifact、门禁、回滚 |

## 课程中的统一不变量

每个页面都反复使用同一条记录格式：

```text
构建结果 = F(提交, 工具版本, 依赖锁定, 配置, 平台, 环境变量, 时间/随机输入)
```

若没有记录某个输入，就不能诚实地声称“可复现”；若某个输入不可锁定，就必须明确其等价标准、容差和失败诊断方法。对肉鸽游戏，随机种子、房间生成参数和掉落表版本也是输入，而不是“测试时顺便看看”。

## 证据路径与实践接口

- **主实践**：构建 `code/repro-game/` 中的无引擎最小游戏，要求干净 checkout、确定种子、测试、构建清单和 CI 复跑。它故意不引入大型引擎，以便先验证底层原则。
- **微实验 A**：在同一仓库制造一次“生成目录误提交”和一次合并冲突，使用 `git status`、`.gitignore`、`git diff --check`、`git revert` 或 `git merge --abort` 解释恢复路径。
- **微实验 B**：把同一构建跑两次，比较 manifest 和产物；再改变时间/种子/工具版本中的一个输入，观察哪类差异是预期、哪类差异是未声明依赖。
- **题目**：题量控制在 6 道，分别检查边界建模、Git 语义、复现证据、引擎迁移、回归诊断与 CI 安全，而不是背命令。

完成本课程的标准是：能解释、能验证、能迁移。能在 Unity 或 UE 中找到对应的项目边界，但不能把“编辑器里点过一次 Build”当成工程能力。
