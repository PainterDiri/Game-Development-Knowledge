# 1. 从“文件夹里的代码”开始：程序、终端与项目

如果你是第一次系统学习编程工具，最容易遇到的不是复杂算法，而是这些问题：

- “我双击了文件，为什么没有运行？”
- “教程让我在终端输入命令，终端到底在控制什么？”
- “我改了代码，为什么游戏还是旧的？”
- “这个目录能删吗？删了还能恢复吗？”

本章先不讲分支、CI 或构建边界。我们只建立后面所有章节都会使用的五个词：**文件、目录、路径、进程、退出码**。

## 1.1 文件、目录和路径

**文件（file）**是一段有名字的数据，例如 `player.c`、`Game.cs`、`room.json` 或 `hero.png`。扩展名通常提示工具如何解释内容，但改名不会自动改变内容本身。

**目录（directory/folder）**用于组织文件。目录可以包含子目录，所以项目形成一棵树：

```text
mini-game/
├── README.md
├── src/
│   └── game.py
├── tests/
│   └── test_game.py
└── assets/
    └── hero.png
```

**路径（path）**是从某个起点找到文件的路线：

- 绝对路径从磁盘根位置开始，只适合当前机器；
- 相对路径从“当前工作目录”开始，更适合项目命令和协作。

例如当前目录是 `mini-game/` 时，`src/game.py` 是相对路径。课程代码、日志和构建脚本应优先记录仓库相对路径，避免把个人用户名和机器目录写进公开结果。

## 1.2 终端不是黑色魔法，而是给程序输入命令

终端（terminal）提供一个文字界面；shell（例如 zsh、bash 或 PowerShell）读取命令，找到对应程序并启动它。

先在课程代码目录练习只读命令：

```bash
pwd                         # 打印当前工作目录
ls                          # 列出当前目录内容
cd code/repro-game          # 改变当前工作目录
python3 --version           # 启动 Python，要求它打印版本
```

每条命令都可以按四个问题理解：

| 问题 | `cd code/repro-game` 的答案 |
|---|---|
| 读取什么？ | 当前目录和目标相对路径 |
| 改变什么？ | 当前 shell 之后解释相对路径的起点 |
| 不改变什么？ | 不修改项目文件，也不进入 Git 历史 |
| 如何判断？ | 再运行 `pwd` 和 `ls` |

初学时不要一次复制十条命令。先运行一条，观察输出，再运行下一条。看到错误时先读第一行和最后一行，确认是“命令找不到”“路径不存在”还是程序本身失败。

## 1.3 程序、进程、标准输出和退出码

磁盘上的 `game.py` 是文件；运行它时，操作系统创建一个**进程（process）**。进程读取输入、占用内存、产生输出，最后结束。

```bash
python3 src/game.py --seed 42
```

这条命令中：

- `python3` 是要启动的程序；
- `src/game.py` 是 Python 要读取的脚本；
- `--seed 42` 是传给脚本的参数；
- 屏幕文字通常来自标准输出或标准错误；
- 进程结束时返回**退出码（exit code）**，通常 `0` 表示成功，非 `0` 表示失败。

在 zsh/bash 中可以观察上一条命令的退出码：

```bash
python3 src/game.py --seed 42
echo $?
```

自动测试和 CI 不能像人一样“看起来差不多”。它们主要依赖退出码和结构化报告判断成功或失败，所以一个失败后仍返回 `0` 的脚本会制造假绿灯。

## 1.4 源文件、生成文件和“我改了为什么没生效”

一个游戏项目往往同时存在：

- 人编辑的源文件；
- 工具根据源文件生成的中间文件；
- 可以运行或发布的最终产物；
- 为了加速保存的缓存。

你修改了 `src/game.py`，却启动了旧的 `dist/game.py`，看到的当然还是旧行为。先用路径确认自己运行的是哪一份：

```bash
python3 src/game.py --seed 42
python3 dist/game.py --seed 42   # 只有构建过后才存在
```

后面第 6 章会正式建立构建系统模型。现在只记住：**编辑对象、运行对象和发布对象可能不是同一个文件。**

## 1.5 第一次项目观察

进入 `knowledge-sets/toolchain-and-git/code/repro-game/` 后运行：

```bash
pwd
find . -maxdepth 2 -type f | sort
python3 -m unittest discover -s tests -v
python3 src/game.py --seed 42
```

逐项回答：

1. 源码在哪里？
2. 测试在哪里？
3. 哪条命令只是读取，哪条命令会启动进程？
4. 测试成功时退出码是什么？
5. 改变 seed 后，哪些输出改变，哪些不应改变？

## 本章练习

### T01-Q1：终端命令的状态

pwd、git status 和 `python3 tool.py` 分别读取/改变什么？

<details><summary>最小提示</summary>

把命令分成观察、修改工作区、启动进程三类。
</details>

<details><summary>讲解与验证</summary>

`pwd` 和 `git status` 主要读取当前环境/仓库状态；运行 Python 启动进程并可能产生文件。用 `git status --short --untracked-files=all` 和 `echo $?` 验证。常见错误是把任何命令都当成会提交或上传。游戏映射：构建命令可能写入产物，但不应自动修改源文件。
</details>

### T01-Q2：把证据写出来

请为本章主题列出一个最小可执行验证，并说明预期结果和失败后的下一步。

<details><summary>最小提示</summary>

不要只写“运行一下”；写出输入、命令、观察对象和判定条件。
</details>

<details><summary>讲解与验证</summary>

合格验证应固定输入并记录命令、退出码、变更的 Git 状态或构建产物；预期结果必须可观察，失败时能缩小到一个阶段或不变量。若结果受时间、网络、缓存或未提交工作影响，应先隔离这些变量。常见错误是只看屏幕上的成功文字，不检查退出码、diff、artifact 或清理后重建。游戏映射：工程质量来自可重复证据，而不是一次“看起来能跑”。
</details>
