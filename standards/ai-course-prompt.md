# AI 课程生成提示

```text
请为本仓库生成下一门课程知识集，并严格只处理这一门课。

执行前：
1. 阅读 AGENTS.md、roadmap/README.md、roadmap/course-index.json 与相关 standards；
2. 检查课程状态、前置课程出口、零基础诊断、目标深度、实践接口和游戏映射；
3. 研究官方文档、标准、论文、源码和大学教材，记录版本、访问日期、用途、限制与冲突；
4. 先画“前置能力 → 概念依赖 → 章节出口”的课程图，再决定页数；D3 课程不要为了少写页面而压缩核心难点；
5. 把 README.md 写成课程首页 + 学习地图：说明先学什么、每章的前置输入/产出/完成证据/下一章用途、章节联系、必修/选读和验收；README 是唯一课程地图入口，不创建 `lessons/00-course-map.md`。

正文写作：
- 默认面对程序小白；第一次出现文件、进程、状态、分支、向量、张量、token、embedding、训练、推理等术语时，先用普通语言解释，再给正式定义；
- 从一个可观察问题开始，逐步建立模型，提供最小示例、可运行代码、故意失败、验证结果和下一节连接；
- 每个核心知识块必须覆盖定义/边界、机制/不变量、例子或代码、失败/取舍、验证和游戏映射；每页必须从可观察任务或失败开始，不能从抽象边界或术语清单开始；
- AI 课程必须区分规则系统、传统机器学习、深度学习、LLM/Transformer 和生成式内容；给出 data → representation → model → loss → update → evaluation → deployment 数据流；
- 线性代数、概率和优化要解释它们在 AI 中的具体作用；LLM 课程要解释 token、embedding、Q/K/V 注意力、位置编码、残差/归一化、训练目标、解码、微调、RAG、工具调用和评估边界；
- 游戏应用要落到 NPC/玩家建模/程序化内容/对话/工具链/端侧推理，并讨论延迟、显存、成本、安全、隐私、确定性和人工审核；AI 课程正文至少拆成 12 个有前后依赖的知识单元，不得用 API 调用和名词列表冒充原理教学；
- Git 或协作课程必须逐条解释命令改变的状态、共享历史风险、验证与恢复，并完整讲任务、分支、PR、review、CI、merge、发布与回滚。

生成后：
1. 更新课程 README、正文、实践、评估、研究笔记和索引状态；
2. 运行 python3 scripts/sync_docs.py、python3 scripts/check_repo.py、git diff --check 与 MkDocs 严格构建；
3. 做一次“零基础可读性审查”和一次“专业深度审查”：前者检查有没有跳步，后者检查有没有只讲结论没有机制/指标/边界；
4. 用户已授权且远程可用时才 commit/push，不使用 --force，不伪造部署成功。
```
