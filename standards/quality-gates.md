# 课程质量门禁

## 状态门禁

- `planned/scaffolded`：只需课程首页、课程地图和研究入口，不公开成套占位页；
- `in-progress`：状态必须明确，未完成页面不得伪装成可学习正文；
- `completed`：正文、题目/答案、实践/解法、来源与必要代码全部可用，并通过以下门禁。

## 自动门禁

- 课程索引、文件与状态一致；
- Markdown 链接有效，MkDocs 严格构建通过；
- 题目与答案默认在同一 `assessments.md` 中，或在拆分布局时 ID 一一对应；提示和解析可折叠；
- 实践题面与解法对应，代码有运行方法、分阶段验收和故意失败；
- 完整课程在 MkDocs 课程子树中直接列出地图、正文、实践和自测页面；
- 没有个人进度、作答、错题、个人练习、密钥或私人绝对路径；
- `sync_docs.py`、`check_repo.py` 和 `git diff --check` 通过。

## 人工门禁

### 正确性与深度

- 关键结论有机制、不变量、边界或可复现证据；
- 代码能运行或明确标注伪代码；
- 复杂度、内存、线程安全、数值误差和网络信任边界没有偷换概念；
- 引擎和库版本与引用一致。

### 课程专属性

- 章节结构来自本课程的难点，而不是只替换模板中的课程名；
- 数学课有推导/数值验证，系统课有测量/诊断，引擎课有生命周期/API 边界，生产课有风险/回滚；
- 没有重复前言、目录复述、API 清单或为了凑题量产生的低价值练习。

### 自学有效性

- 题目能区分记忆与理解；
- 每题有提示、推理、边界、常见错误、验证和游戏迁移；
- 实践少而精，具有验收、故意失败和替代方案；
- 学习者无需维护形式化学习档案。

### 视觉与可访问性

- 复杂状态、流程、依赖或时序优先用合适图示，简单内容不强行画图；
- 图示在亮/暗主题均可读，并有文字结论；
- 图标用于导航和语义提示，不替代文字；
- 折叠答案、代码和表格在窄屏下可用。

### 游戏与公开发布

- 至少一个案例落到运行时、工具、服务端或生产；
- 公开案例与教学推断明确区分；
- 资源许可证可说明，不复制商业项目私有资料；
- `completed` 只表示公开课程完成，不表示任何学习者学完。

## 正文有效性门禁

- `README.md` 已合并课程首页与地图，并给出先读顺序、前置诊断、出口、实践和练习入口；
- 每个核心章节至少有问题场景、机制模型、详细示例/代码、失败或边界、验证和游戏映射中的大部分证据；
- 完成课程的正文不是若干提纲拼接：学习者可以不打开实践页，先理解核心机制并运行一个验证；
- 章节可合并则合并，页面数量和目录层级不作为质量证明；
- `practice.md`（如采用）同时包含题面、最小版本、提示、参考路线、代码入口、验收和常见失败；
- `assessments.md` 默认同页折叠答案，题目 ID、提示和解析一一对应；
- `references/` 与术语索引不在主学习导航中，且没有用维护资料代替教学内容。
