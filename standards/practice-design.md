# 实践设计标准

## 练习选择模型

每个练习必须有高信息增益、可复用、可测量、可缩放。四项中有两项不满足就删除，不用练习数量制造完成感。

## 实践题面

`labs/README.md` 至少包含：

- 要验证的问题、范围和约束；
- 起始材料、版本、输入与预期输出；
- 标准版与 2 小时缩减版；
- 正常、边界和故意失败三类验收；
- 最少必要的测试、日志或性能证据。

个人实现可放任意目录；如在仓库中工作，按需使用 `.practice/<course>/`。不要求学习者撰写实验报告或维护决策日志。

## 参考解法

`labs/solutions.md` 使用 `<details>` 折叠并包含：

1. 不直接泄露实现的最小提示；
2. 推荐拆解顺序和关键不变量；
3. 参考实现/伪代码/结构图，或 `code/` 中的可运行入口；
4. 验证命令、预期结果及隐蔽错误的识别方法；
5. 常见失败、调试路径和修复理由；
6. 至少一个替代方案及取舍；
7. 肉鸽、Unity、UE、服务器或工具链迁移。

参考解法不是唯一答案。大型 Unity/UE 实践可以只提供关键组件、场景结构、测试夹具和验证方法，不复制整个商业级工程。

## 游戏实践隐藏成本

考虑引擎/包版本、输入设备、帧率与固定时间步、资源引用和序列化、随机种子、调试可视化、资产版权、体积和打包平台。

## 肉鸽实践要求

道具系统至少说明事件/消息、modifier/effect 管线、标签/查询、组合优先级或数据定义与运行时实例分离之一，并处理冲突、顺序、幂等、撤销和存档表示。随机生成支持种子、重放或最小复现日志。

## 题目配额

每章 2–4 道高质量题，优先：解释反直觉现象、修 bug、比较设计取舍、为游戏系统写不变量/测试。题目 ID 稳定且唯一，并与答案和评分表对应。
