# 课程主实践设计规范

## 目的

每门课程只保留一个与本课知识直接相关的主实践。实践不是“把参考项目跑起来”，而是让学习者在安全副本中完成一组有顺序的状态变化，并用测试、命令输出、截图中的关键字段、性能数据或可检查工程状态证明结果。

## 交付模式：默认下载，仓库副本只是备选

### 模式 A：代码、脚本、数据或本地服务

有可复用文件时，课程网站提供 ZIP。解压后根目录必须有 `START_HERE.md`，并尽量使用短路径：

```text
<course>-practice/
├── START_HERE.md
├── workspace/<project>/   # 可编辑绿色基线，或 starter/<project>/
├── reference/<project>/   # 只读对照
├── fixtures/              # 如需要
└── manifest.json
```

学习者默认把 ZIP 解压到仓库外，例如 `~/game-labs/c-programming/` 或 `C:\game-labs\c-programming\`，直接进入 `workspace/<project>`。绿色基线只证明环境可运行；题面必须明确要求学习者删除、补全、重写、注入失败、增加测试或改变设计，不能把原样运行参考代码算作完成。

### 模式 B：Git、命令行和工具链

如果学习目标包含 Git 历史或命令状态，ZIP 提供普通文件基线，不携带隐藏 `.git/`。实践页逐步写明：

- 从哪个目录执行 `git init`；
- 每条命令前后的工作区、暂存区、本地引用、远端引用或文件系统状态；
- 何时使用一次性临时仓库/本地裸远端；
- 哪些命令禁止在真实项目执行；
- 如何保存恢复点、退出失败流程并验证没有丢数据。

不能只写“自行建仓库并练习 merge/rebase”。

### 模式 C：Unity、Unreal 或 GUI 工具

有合法且体积可控的工程骨架时，ZIP 只打包可迁移源资产与配置：Unity 的 `Assets/`、`Packages/manifest.json`、必要 `ProjectSettings/`；UE 的 `Config/`、`Content/`、`Source/` 与项目描述文件。不得打包 `Library/Temp/Logs/UserSettings`、`Binaries/Intermediate/Saved/DerivedDataCache`。

无必要代码或无法安全分发完整工程时，可以不强行提供 ZIP，但实践页必须像实验手册一样给出：

1. 引擎/Hub/IDE 的明确版本范围；
2. 新建或打开项目的具体入口、模板和目录名；
3. 每一步菜单路径、对象/组件/资源名称、关键 Inspector 字段和值；
4. 操作后的 Hierarchy/Project/Console/Profiler 可观察结果；
5. 保存、撤销、重开项目和清理生成缓存的方法；
6. 一个故意失败、诊断顺序和恢复步骤；
7. 无鼠标或菜单变化时可用的替代路径，并标注版本差异。

截图只在降低定位成本时使用，且必须脱敏；文字步骤和验收不能依赖截图才成立。

## 仓库内 `.practice/` 备选路径

已经克隆本仓库、希望就近实践的学习者可在仓库根目录运行：

```bash
python3 scripts/init_practice.py --course <slug>
git check-ignore -v .practice/<slug>
git status --short --untracked-files=all
```

`init_practice.py` 优先复制 `starter-code`，其次复制 `editable-baseline`。它拒绝覆盖已有目录。使用仓库内备选路径时，学习者只编辑 `.practice/<slug>/`；若实践 Git，可在更深一层项目目录内 `git init`，并用 `git rev-parse --show-toplevel` 确认没有操作外层课程仓库。使用网站 ZIP 时则只编辑仓库外的 `workspace/` 或 `starter/`。

`.gitignore` 只保护未跟踪文件。若误改已跟踪教材文件，应先用 `git diff -- <path>` 检查并把成果复制到安全位置，确认备份后再考虑 `git restore`。不得使用 `git add -f .practice/...`，不得在仓库根目录运行 `git clean -fdx`，因为它会删除被忽略的个人实践。

## 实践页必须具备的结构

1. **目标与非目标**：本课究竟验证什么，不声称验证什么；
2. **最快开始**：下载链接、推荐解压路径、入口命令/引擎操作和预期基线；
3. **独立最小版本**：在没有可选拓展时也能完成的最小闭环；
4. **分阶段指导**：每阶段写输入、动作、状态变化、完成条件和恢复点；
5. **必须由学习者完成的改动**：防止把运行参考实现当学习；
6. **故意失败**：可安全复现、可诊断、可修复，并留下回归测试；
7. **验收矩阵**：功能、边界、失败原子性、可复现性、性能/资源、工程隔离按本课需要取证；
8. **常见失败**：现象 → 最可能原因 → 先看哪里 → 修复 → 如何确认；
9. **清理与恢复**：只删除明确拥有的生成物，不使用无边界递归删除；
10. **可选拓展**：不得伪装成最低完成条件。

长实践可以提供阶段指导和检查点，但不提供一个可直接照抄到底的“唯一解题路线”。参考实现只用于比较契约、恢复文件和研究替代方案。

## `practice-bundle.json`

有公开文件的课程使用 schema 2 显式白名单。至少包含：

- `quickStart`：在可编辑目录执行的非空命令列表；
- `starter-code` 或 `editable-baseline`：学习者入口；
- `reference-code`：只读对照；
- 每项可选 `target`，用于把包内路径压平；
- `exclude`：课程特有缓存和生成物。

下载包不得包含课程答案页、个人状态、密钥、日志、绝对路径、缓存或平台发布产物。打包器应固定 ZIP 时间戳、拒绝越界路径和重复目标，并生成根目录 `START_HERE.md`。

## 验收证据的边界

- 构建通过不等于规则正确；
- 参考测试通过不等于学习者掌握；
- 一次性能更快不等于普遍优化；
- Sanitizer 无报告不等于没有未定义行为；
- 本地双客户端不等于 MMO 规模；
- 能打开 Unity/UE 工程不等于资产、构建和版本控制边界正确。

实践必须明确自己实际取得的证据和仍未覆盖的范围。
