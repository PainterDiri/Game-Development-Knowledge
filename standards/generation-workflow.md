# 知识集生成执行流程

每次只生成 `roadmap/course-index.json` 中下一门未完成课程，除非用户明确指定其他课程。

## Step 0：读取上下文

- 读取根目录 `AGENTS.md` 和相关标准；
- 读取课程索引、路线、前置课程的公开内容；
- 确认 `depth`、`phase`、`practice` 和前置依赖；
- 不读取或生成个人进度、作答、错题和决策日志。

## Step 1：研究

优先官方教材/课程、标准、引擎文档、论文、源码和可靠技术分享。记录版本、日期、适用范围和不确定点，先写入 `references/research-notes.md`，不要把搜索摘要直接当正文。

## Step 2：定义出口能力

写出 5–10 条可观察的“完成后能做什么”。每条可以通过口头解释、代码、测试、图示、性能数据或反例验证，但不要求学习者维护完成表。

## Step 3：规划章节

先建立 `lessons/00-course-map.md`，列章节问题、前置知识、核心概念、游戏映射、实验、难点和必学/选学。课程地图通过校验后再写正文。

## Step 4：生成正文与素材

按章节逐个生成。图表优先 Mermaid、ASCII 或可再生成脚本；二进制资产说明来源和许可证。代码必须有版本、运行命令、预期结果和限制。

## Step 5：设计实践与解法

每门课最多 1 个主实践 + 2 个微实验。

- `labs/README.md`：范围、输入、输出、失败案例、验收清单、估计时间和 2 小时缩减版；
- `labs/solutions.md`：折叠的最小提示、拆解顺序、关键不变量、参考实现/伪代码、验证命令、常见失败、替代方案和游戏迁移。

个人代码位置由学习者自行决定；若在仓库中工作，按需使用 `.practice/<course-slug>/`。不要求实验报告或决策日志。

## Step 6：生成评估

必须有稳定唯一的题目 ID、每章 2–4 道高信息量题、一道综合题，以及一一对应的最小提示、答案、推理、边界、验证和游戏迁移。答案使用 `<details>` 折叠，支持“心答/纸答后快速核对”，不要强制保存作答过程。

## Step 7：本地校验

```bash
python3 scripts/sync_docs.py
python3 scripts/check_repo.py
git diff --check
.venv/bin/mkdocs build --strict
```

再按 `quality-gates.md` 人工检查技术正确性、版本适配、实践可复现、题解完整、引用、隐私和防注水。

## Step 8：更新索引与 Git

- 更新公开课程内容状态：`planned → in-progress → completed`；
- 同步 MkDocs 内容和索引；
- 写清变更摘要、验证结果和未解决问题；
- 完成后创建清晰提交；
- 有用户授权且远程可用时 push；不得使用 `--force` 或伪造成功。
