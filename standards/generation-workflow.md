# 课程生成流程

默认一次只生成课程索引中按 `order` 排序的下一门未完成课程，但“下一门”不代表仓促填满页面。每门课必须先完成教学设计，再写正文。

```mermaid
flowchart LR
    A[读路线与前置出口] --> B[做零基础诊断]
    B --> C[研究可靠来源]
    C --> D[画概念依赖图]
    D --> E[设计章节与证据]
    E --> F[写 README 课程地图]
    F --> G[逐页写可运行正文]
    G --> H[实践与评估]
    H --> I[自动检查 + 人工教学审查]
    I --> J[同步、构建、提交]
```

## 1. 定位与前置

读取 `AGENTS.md`、`roadmap/README.md`、`roadmap/course-index.json`、本课程相关 standards 和前置课程的公开出口。为课程写出一条“不会什么 → 学会什么”的链：

```text
前置能力 → 诊断题/补桥 → 第 1 个可观察任务 → 核心概念 → 综合出口
```

如果课程本身是零基础入口，也要先教文件、输入、输出、状态、命令或符号的最小含义；不要默认读者已经会使用工具。

## 2. 研究

优先官方文档、标准、论文、源码和大学教材。先在 `references/research-notes.md` 记录版本、访问日期、关键事实、用途、限制、冲突和不确定性。AI 和引擎 API 必须重新核对当前稳定版本；原理与版本绑定细节分开写。

## 3. 课程设计审查（写作前必须完成）

在 README 中回答：

- 学习者最容易在哪一步迷路？
- 哪些概念严格依赖前一概念？
- 每章读完后能运行、推导、测量或诊断什么？
- 哪些页是主干，哪些是选读？
- 如果不打开实践页，正文是否已经足以理解核心机制？
- D3 课程是否给难点足够篇幅，是否把低价值内容压缩掉？C、线性代数、数据结构、系统和 AI 是否按教材级难点拆成足够多的连续知识单元？
- 每章是否都有明确的“上一章产物”和“下一章用途”？若没有，必须合并或重排。
- 本课程如何连接 `RogueSlice`，以及失败时如何退回独立最小版本？

## 4. 生成正文：从具体到抽象再回到具体

先写章节依赖表，再写页面。每页开始不得直接给抽象边界或术语总表；必须先展示任务、输出或故意失败。页面完成后回填课程地图中的完成证据。

每个核心知识块按需要组织，但必须让学习者经历：

1. 一个任务、现象或故意失败；
2. 普通语言解释与正式术语；
3. 最小模型/公式/状态图；
4. 逐步例子和可运行代码；
5. 改变一个输入，观察一个结果；
6. 失败、边界和专业取舍；
7. 游戏映射；
8. 与下一节的连接。

长课程不要因为“统一模板”而只有 4–6 章。C、线性代数、数据结构、系统、软件工程和 AI 等 D3 课程应按概念依赖拆成足够多的连续章节；每章只解决一个可验证的大问题，必要时把一个核心难点拆成多章。

## 5. Git 协作课程的最低覆盖

Git 正文必须逐条解释常用命令，而不是只给命令表。最低包含：

- `init/clone/status/add/restore/diff/commit/log/show`；
- `branch/switch/fetch/pull/push`；
- `merge/rebase/cherry-pick/revert/reset/reflog/bisect`；
- `.gitignore`、标签、远端、LFS/锁定和文本/二进制资产；
- 分支保护、PR/MR、review、CI、合并策略、集成分支、发布分支/标签、回滚；
- 冲突的意图分析、验证和事故后的恢复。

每个命令都要写“状态变化、是否改写共享历史、如何验证、如何恢复”。

## 6. AI 课程的最低覆盖

AI 课程必须给出数据流：

```text
data → representation → model → loss → gradient/update → evaluation → inference/deployment
```

LLM/Transformer 课程至少解释 token、embedding、位置/顺序信息、Q/K/V 注意力、残差与归一化、训练目标、推理解码、上下文长度、微调/RAG/工具调用的边界，并用简化模型和指标验证。游戏 AI 课程要区分规则式决策、机器学习策略和生成式模型，不把它们混为“AI”。

## 7. 练习、实践和发布

默认使用一个 `practice.md`，合并题面、环境、提示、路线、验收、故意失败和常见失败；题目放在 `assessments.md`。完成前运行：

```bash
python3 scripts/sync_docs.py
python3 scripts/check_repo.py
git diff --check
.venv/bin/mkdocs build --strict
```

再人工检查：初学者能否从第一章开始，章节之间是否有真实依赖，命令/代码是否可运行，重要程度与篇幅是否匹配，版本/引用/版权/隐私是否正确。只有正文、实践、评估、来源和索引状态全部相符时才能标记 `completed`。只有远程、凭据与授权均满足才可 push。
