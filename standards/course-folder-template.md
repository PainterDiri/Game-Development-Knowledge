# 文件职责与可变结构

课程目录用于让学习者和工具快速找到**可学习内容**，不是规定每门课必须一样长。页面数量不等于质量，但 D3 课程不能以“页面少”为目标压缩必要推导和实验。

## 默认骨架：先研究，后创建正文

```text
knowledge-sets/<slug>/
├── README.md                    # 课程首页 + 学习依赖图 + 章节地图
├── lessons/                     # 按概念依赖排列的正文，可有任意合理数量
├── practice.md                  # 默认主实践、提示、路线、验收和失败
├── assessments.md               # 题目 + 折叠解析
├── code/                        # 可运行实验/参考实现，按需创建
├── references/                  # 研究笔记与书目
├── integration-contract.md      # 需要接入主项目时创建
└── practice-bundle.json         # 有公开代码/fixture 时创建
```

不要预填大量“待填写”页。研究和课程图完成后，按本课的实际难点创建正文。`README.md` 是唯一的课程首页与课程地图入口；新课不得创建 `lessons/00-course-map.md`。仓库中的同名文件仅作为历史 scaffold 兼容物保留，不能加入公开导航；课程转为 `completed` 前必须删除它，除非它承担与 README 不重复的独立正文职责。

## 课程首页最低内容

README 必须直接回答：

- 零基础学习者从哪里开始；
- 前置诊断与补桥；
- 课程核心问题和为什么按当前顺序学习；
- 逐章依赖、输入、产出和证据；
- 必修/选读边界；
- 实践、题目、代码入口和主项目接缝；
- 完成课程后能解释、实现、验证和迁移什么。

## 文件职责

- `lessons/`：正文必须能独立教学，不得只是提纲、目录或 API 摘要；页面顺序必须对应真实概念依赖，页面之间要明确输入、产出与下一页用途。
- `practice.md`：实践题面、环境、最小版本、提示、参考路线、验收、故意失败、常见失败和迁移；
- `assessments.md`：题目与答案同页，题目少而精，答案需有推理、边界、验证和游戏映射；
- `references/`：记录来源、版本、日期、用途、限制、不确定点；不代替正文；
- `code/`：说明语言/版本、命令、预期结果和已知限制；不提交缓存、构建输出、私人状态或绝对路径；
- `integration-contract.md`：写清输入/输出、状态所有者、适配器、允许修改、回滚和主项目冒烟。
