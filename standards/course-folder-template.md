# 文件职责与可变结构

课程目录用于让学习者快速找到**连续、可学习、可验证**的内容，不是为了统一页数。课程地图先确定概念依赖，再决定章节数量；D3 课程不得用短提纲替代教材式讲解。

## 默认骨架

```text
knowledge-sets/<slug>/
├── README.md                    # 课程首页、前置诊断、章节地图和学习出口
├── lessons/                     # 按概念依赖排列的正文；每章末尾包含练习与折叠讲解
├── practice.md                  # 本课程唯一主实践：题面、指导、代码入口、验收与失败诊断
├── code/                        # 只读的公开起始代码/参考实现，按需创建
└── practice-bundle.json         # 有公开代码或 fixture 时创建
```

不再为课程创建独立的 `assessments.md`、`assessments/`、`references/` 或 `integration-contract.md`。研究过程是生成阶段的内部工作，真正支持正文的来源应在相关段落或章节末尾就地标注；不发布单独的“研究笔记”和“参考书目”页面。

`README.md` 是唯一课程首页与地图入口。新课不得创建 `lessons/00-course-map.md`；历史 scaffold 在课程完成前必须删除。

## 课程首页最低内容

README 必须回答：

- 零基础学习者从哪里开始，前置不足怎样补桥；
- 课程核心问题和章节为何按当前顺序排列；
- 每章的前置输入、核心产出、完成证据和下一章用途；
- 哪些章节必修，哪些是选读拓展；
- 本课程唯一主实践是什么，怎样在 Git 隔离的个人目录中开始；
- 完成课程后能解释、实现、验证和迁移什么。

## 文件职责

- `lessons/`：正文必须能独立教学。每章从一个可观察任务或失败开始，讲清机制、例子、边界、验证和游戏用途；章末练习由独立出题人按知识密度决定数量，不得固定凑数；每题就地提供完整讲解，提示可选。
- `practice.md`：只承载一项与本课程知识直接相关的主实践。必须包含环境、最小版本、分阶段指导、关键代码、验收、故意失败、常见问题、清理方式和 Git 隔离检查。
- `code/`：仓库内的公开代码是**只读教材资产**。学习者不得直接修改；必须复制到 `.practice/<course-slug>/` 或仓库外再实践。代码需说明语言/版本、命令、预期结果和限制。
- `practice-bundle.json`：显式白名单打包公开代码/fixture；网页正文和练习讲解不进入 ZIP。

## 章节内练习格式

练习不按固定题量凑数。窄章节可以只有 1 题，多机制或数学/算法章节可以有 5 题以上；出题人必须在内部验收中说明题量取舍，并在适合本章时覆盖至少两类能力（解释机制、预测结果、修复失败、计算/证明、设计或实现、迁移与取舍）；窄章只有一类核心产出时不得为了凑第二类而注水。题目应有具体输入、约束或判定标准；推荐格式见[章末出题人规范](question-authoring.md)。

```markdown
## 本章练习

### C04-Q1：题目名
题面……

<details><summary>最小提示</summary>
只提示下一步，不直接给答案。
</details>

<details><summary>讲解与验证</summary>
给出推理过程、边界、常见错误、验证方法和游戏中的用途。
</details>
```

练习必须紧跟它所依赖的知识，不能把所有题堆到课程末尾让学习者来回查找。
