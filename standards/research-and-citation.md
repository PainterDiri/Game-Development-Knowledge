# 研究与引用规范

## 研究先于写作，但不发布研究日志

生成课程前必须检索可靠资料、核对版本和冲突；研究记录可存在本次工作临时文件或任务上下文中，完成后不进入公开课程目录。仓库不再维护独立“研究笔记”或“参考书目”页面，避免把维护材料误当教学内容。

真正影响教学结论的来源应**就地出现**：在相关段落后给出链接，或在章节末尾加入简短的“本章资料依据”。只列实际使用过的资料，不堆链接。

## 来源优先级

1. 语言标准、官方文档、引擎官方手册/API、论文原文、官方源码与样例；
2. 大学公开课程、出版社教材、维护良好的开源项目；
3. 有作者、版本、实验数据和代码的技术文章；
4. 博客、论坛、视频只用于发现线索，不作为关键结论的唯一依据。

技术细节若会随版本变化，必须查询当前官方资料，并在正文写明适用版本和访问日期。若只能得到旧版资料，要明确迁移风险。公开案例与教学推断必须分开标注。

## 就地引用格式

```markdown
> 资料依据：[Clang AddressSanitizer 文档](URL)（访问日期：YYYY-MM-DD）。
> 用于：解释该工具能检测的错误类别；限制：具体开关随编译器版本变化。
```

章节可以有 2–6 条这样的短来源说明，但不能用来源列表代替机制讲解、代码和验证。

## 版权与不确定性

- 用自己的话解释，不复制教材整章、商业源码、素材或私有文档；
- 无法从可靠来源确认的内容要标注“不确定”或删去；
- API 示例注明版本，跨版本原则与版本绑定细节分开；
- 公开链接前检查来源、许可、访问日期和它支持的具体结论。
