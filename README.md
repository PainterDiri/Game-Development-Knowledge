# 游戏开发究极知识包

这是一个以计算机科学培养方案为基础、以游戏开发为主线、以「可做出并发行一款小型肉鸽动作游戏」为长期目标的公开学习知识库。

> 当前仓库完成的是前置环境与生成规范：学习路线、课程索引、实践体系、AI 生成标准、质量门禁和 MkDocs 文档站。课程知识集按 `roadmap/course-index.json` 的顺序逐门生成到 `knowledge-sets/`。

## 阅读方式

常驻公开网站：

```text
https://painterdiri.github.io/Game-Development-Knowledge/
```

网站会自动保存最后阅读的课程页面、章节和滚动位置。下次打开首页会继续上次学习，不需要账号、打勾、`progress.md`、作答日志或错题本。进度只保存在当前浏览器，不上传 GitHub，每个访问者天然独立。

每门课程公开包含：正文、少量高价值题目、折叠提示、答案与详细解析、实践题面、参考路线和验收方法。

## 维护者快速开始

```bash
# 首次安装文档站
make install

# 同步公开课程并本地预览
make docs-serve

# 检查目录、链接、题解、隐私和严格构建
make check
```

普通学习者只需访问网站，不需要 clone 仓库或安装 MkDocs。

## 实践代码

个人实践代码可以放在任何习惯的位置。如果放在本仓库，按需创建：

```text
.practice/<course-slug>/
```

`.practice/` 已被 Git 忽略；不需要提前为每门课创建目录，也不强制维护学习日志、实验报告或架构决策文档。

## 仓库结构

- `培养方案图片.png`：培养方案原图，仅作为课程映射参考；
- `roadmap/`：总体路线、实践里程碑和课程元数据；
- `knowledge-sets/`：公开课程正文、实验、题目、答案、解析和参考代码；
- `standards/`：知识生成、研究、实践、架构和质量规范；
- `docs/`：MkDocs Material 文档站源码与自动续学脚本；
- `scripts/`：课程脚手架、文档同步和仓库检查；
- `mkdocs.yml`：文档站配置。

## 学习原则

1. 先建立可运行的最小系统，再逐层抽象；
2. 用游戏问题驱动计算机科学，但不牺牲原理；
3. 每门课最多一个主实践和两个微实验；
4. Unity/UE 的 API 随版本变化，底层原理必须可迁移；
5. 删除形式主义：不强制抄笔记、打卡、建错题本或写报告；
6. 公开仓库不包含个人信息、个人进度、作答和实践产物。
