# 知识集现状审计：既有课程、教学规范与可执行证据

> 本轮审查起始日期：2026-09-06。只评估公开课程与工程，不记录或推断任何学习者的进度。执行者依次进行出题、求知、专业审查视角走查，**不是独立人员评审或真实学习者实验**。

## 1. 范围与结论

本轮遵循“只优化已有课程与规范，不生成下一门课”的范围：

- 索引共 **27 门**；工具链与 Git、C 程序设计两门已发布，分别有 9、14 个正文章节；另 25 门仍是准备中的骨架。
- 未生成新课程，未修改课程索引状态、前置或排序，未扩写 25 门骨架。
- 保留一课一个直接相关的主实践，以及浏览器本地续学、个人 `.practice/` 隔离；不新增学习档案。
- 主要成果不是篇幅增加，而是修复两处教材与实现冲突、为关键教学补桥、增加可执行回归，并将“知识覆盖”与“已经验证的能力”分开。
- **不能据此宣称 23 个章节都已逐句复核、逐例运行，也不能宣称已达到完整计算机专业或 MMO 工程的培养效果。** `completed` 保持既有公开发布状态，不表示本轮全面重新认证。

此前版本同时写着“两门已发布”“只有工具链有正文”“下一门是 C”，彼此矛盾；本轮改为以下可核对的范围与结果，不再用缺少量表的字母评级。

## 3. 规范如何服务真正掌握

新增[教学覆盖与证据规范](../standards/teaching-evidence.md)，并同步生成流程、课程提示、引用规范、实践设计与质量门禁：

1. **先做核心能力地图**：前置 → 正文落点 → 不看答案的独立任务 → 证据及其限制。旧目录不是唯一覆盖基准，需要与专业知识模型、标准或大学课程核对取舍。
2. **消除隐含前置**：第一次实际使用术语、符号、命令或 API 时给必要模型；重要内容不能“提到就算教过”。补桥不等于提前讲完整门后续课。
3. **用因果链组织教材**：问题、模型、逐步推演、关键条件改变后的反例、独立判断与迁移；各课程采用适合自己的结构，不强迫复制标题模板。
4. **教材与参考实现共享契约**：声明不支持的功能可以简化，已经承诺的输入边界、失败语义不能以“教学代码”为由省略。
5. **练习检验而不是复读**：删除重复通用题；答案给推理、边界、错误分析与可判定验证。保留稳定题号，不为连续编号重排既有引用。
6. **诚实记录审查范围**：角色走查不冒充独立评审；运行通过不代表所有输入、所有平台或全部课程已经验证。

两门课程首页均新增核心能力与证据边界表。表格是教学承诺和复核入口，不是自动给学习者打分。

## 4. 游戏主线与专业覆盖的关系

保留 Unity/2D 肉鸽作为可完成项目的主线，但不把“第一版单机游戏用不到”误写成“专业体系可以不教”。

- 语言、算法、内存、数学与数值、系统、图形的原理不能只换成游戏术语或引擎 API 列表。
- C# 与 C++ 的语言桥接分别由 OOP、UE 前置安排；不能假定会 C 就已经会托管对象模型、RAII 或引擎生命周期。
- 实时多人同步与持久在线服务是不同能力：前者处理权威、tick、预测/校正和丢包，后者处理事务、幂等、复制、一致性、恢复和容量。
- 在线服务可不阻塞单机纵切片，但对多人/服务器方向是必修出口；本地双客户端演示不能证明 MMO 规模。
- 产品与人机交互、可访问性、安全和运维也要在承接课程留下可检验产出。

具体承接课程与出口写在新规范的覆盖表。**这是后续逐门生成时的要求，不是本轮已经生成或验证了这些知识。**

## 6. 未完成的复核边界与下一轮优先级

1. **C 其余章节**：本轮没有逐一重新运行动态分配、文件持久化、调试器等全部示例；固定容量主实践不能替代这些能力的章节检验。后续修订优先核对第 11–13 章的所有权、I/O 错误和 UB 教学链，再逐段回查第 1–7、10 章。
2. **工具链 Git 情景**：第 1–5 章保留既有正文，未在本轮逐个重做远程协作、冲突恢复与团队发布情景；本地构建测试不证明这些练习都已无跳步。
3. **真实学习反馈**：本轮只有执行者角色走查，没有独立读者盲做结果；“通俗易懂”和长期迁移不能仅靠模型自评确认。
4. **平台矩阵**：未本地验证 Windows/Linux 全部命令或触发远程 CI；新构建保护面向可信本地单进程误操作，不提供原子发布、恶意并发防护或完整供应链认证。
5. **后续课程**：仍一门一门研究与生成，不为填满总览提前生成空章节或批量正文。需要继续重审已有课程时，也应限定一条教学链完成正文、练习与验证，而不是再堆一套规范。
