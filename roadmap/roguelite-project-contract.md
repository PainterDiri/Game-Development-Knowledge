# 小以撒纵切片：共享项目契约

## 结论先行

把实践逐门课程拼成一个类以撒肉鸽是**可行的**，但“所有课程都直接改同一个 Unity 场景”不可行：低层课程需要快速、可测量、跨引擎的载体；网络与 UE 课程有不同的运行时边界；过早把所有内容绑进 Unity 会让一个错误阻塞后续学习。

本路线采用一个更稳的折中：

- 维护一个学习者自己的 `RogueSlice` 主仓库；
- 从阶段 2 开始，Unity 项目是主要集成目标，但每个课程只通过一个小接缝交付一个功能；
- C、算法、数学、操作系统等课程默认产出**可导出的结果**（测试数据、库、配置、基准、算法模型），而不是把课程正文改写成 Unity API 课；
- 网络课程使用旁路服务/本地多进程实验，先验证权威性、预测和故障，再决定是否进入主游戏；
- UE 课程复制一个系统做迁移对照，不把 Unity 项目改造成双引擎工程；
- 发行课程才把主项目冻结成候选版本，不把每门课的实践都当成最终产品功能。

## 推荐目录

```text
RogueSlice/
├── Unity/                       # 唯一的主 Unity 项目
│   ├── Assets/Game/             # 领域规则、运行时、表现和工具
│   └── Packages/                # 需要稳定复用的 Unity 包
├── tools/                       # C/Python 等引擎无关实现、转换器、基准
├── labs/                        # 课程独立实验；可删除、可重跑
├── contracts/                   # 跨课程稳定输入/输出契约
├── test-fixtures/               # 小型固定 seed、存档和网络故障样本
└── artifacts/                   # 本地构建、报告和截图；不提交
```

`Unity/` 不是所有课程的工作目录。实践代码下载包中的文件必须先按照接缝说明放入 `tools/`、`contracts/`、`Unity/Assets/Game/` 或 `labs/`，而不是整个目录覆盖主项目。

## 十个纵切片接缝

| 接缝 | 主要课程 | 最小功能 | 进入主项目的形式 |
|---|---|---|---|
| F0 可复现工程 | 工具链与 Git | build ID、内容版本、seed、回归证据 | `contracts/run-context.json` + CI/脚本 |
| F1 运行时基础 | C、数据结构、OOP | 容器、队列、对象生命周期、日志 | 引擎无关库或对照实现；Unity 只接 API |
| F2 房间与规则 | 离散数学、算法 | 房间图、可达性、空间查询、生成约束 | 固定输入/输出 fixture + C# 适配器 |
| F3 战斗空间 | 线性代数、图形、OOP | 坐标、瞄准、命中框、反馈 | Unity 小场景和可视化调试层 |
| F4 内容与敌人 | 概率、DSL、脚本、AI | 掉落、状态效果、敌人决策、内容校验 | 数据文件 + 规则/AI 组件 |
| F5 核心纵切片 | 软件工程、引擎架构、Unity 生产 | 房间清空、战斗、奖励、重启、暂停 | 主 Unity 项目直接集成 |
| F6 持久化与资源 | 数据库、多媒体、资源管线 | 存档 schema、导入、加载、音频反馈 | Unity 编辑器/运行时工具 + 迁移测试 |
| F7 诊断与性能 | 组成、OS、优化工具 | 帧预算、任务队列、profile、故障报告 | Unity profiler fixture + 独立基准 |
| F8 联机旁路 | 计算机网络、在线服务 | 权威房间状态、重连、观测、服务故障 | 本地服务/测试 harness；可选接入主项目 |
| F9 引擎迁移 | UE 玩法编程 | 重建 F3/F4/F5 的一个系统 | 独立 UE 项目，不回写 Unity |
| F10 发行候选 | 发行与毕业 | 构建、安装、迁移、回滚、发布说明 | 冻结主 Unity 项目并打包 |

“进入主项目”不是完成课程的唯一证据。引擎无关课程的正确性仍以自己的测试、推导、基准或故障实验为准；主项目只消费经过验证的契约。

## 每次集成的四步

1. **先通过课程自身门禁**：先在独立目录完成测试、测量或反例，不让 Unity 编辑器掩盖原理错误；
2. **生成可携带产物**：代码、配置、数据、测试 fixture 或小型 Unity 包，并写明版本、依赖、所有权和生命周期；
3. **按契约接入**：只修改允许的目录，保留适配层；若需要大范围改动，先拆成新的接缝，不直接共享内部状态；
4. **跑主项目冒烟**：固定 seed 启动、进入房间、完成最小动作、重启并检查日志；失败时可以整块回滚，不影响其他课程。

## 不变量

- 领域规则不依赖 UI、具体场景对象、编辑器状态或平台 API；
- 每个随机系统都有显式 seed 和最小回归输入；
- `ItemDefinition`、`ItemInstance`、效果解析顺序和存档 ID 分离；
- 每个接缝都有一个拥有状态的模块、一个适配器和一条可观察路径；
- 课程成果默认可删除、可重建、可回滚；不以“把主项目改到不能打开”为完成证据；
- 网络实验不把客户端输入当权威事实，UE 迁移不把蓝图或 C++ 选型伪装成唯一答案。

## 时间与范围控制

如果主项目接入导致环境修复超过实践时间的一半，先退回课程的独立最小版本，记录接缝失败原因，再继续学习。可以暂时只保留一个可运行房间、一个敌人和一个奖励；不要为了“看起来完整”牺牲可复现、可测试和可回滚。
