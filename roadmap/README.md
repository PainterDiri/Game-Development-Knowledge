# 学习路线总览

## 目标画像

最终目标不是“会点 Unity/UE”，而是形成一套能够独立完成以下工作的能力：

- 读懂并实现游戏程序的核心数据结构、算法、内存与并发逻辑；
- 在 Unity 或 Unreal Engine 中构建可维护的玩法、战斗、AI、UI、存档、资源和工具系统；
- 能解释帧循环、输入、碰撞、动画、渲染、音频、网络同步、性能瓶颈和构建发布；
- 能用工程化方法管理规模增长：命名、模块边界、数据驱动、事件、测试、日志、版本控制、CI；
- 完成一个有明确范围、可游玩、可测试、可打包、可发布的“小以撒”式 2D 肉鸽动作游戏。

## 三条能力线

| 能力线 | 解决的问题 | 主要课程 |
|---|---|---|
| 底层与算法线 | 为什么代码正确、快、稳，如何接近引擎内部 | C、数据结构、算法、离散数学、组成原理、体系结构、操作系统 |
| 游戏系统与引擎线 | 如何把规则变成可扩展玩法并落地到 Unity/UE | OOP/C++、软件工程、数据库、网络、图形/多媒体、AI、引擎实践 |
| 产品与交付线 | 如何把原型做成可玩的产品并交付 | 设计文档、工具链、调试、性能、测试、打包、发行、毕业设计 |

## 深度分级

- **D3 深入掌握**：能从原理推导，独立实现简化版，能解释取舍并处理边界情况。用于 C++、数据结构/算法、操作系统、网络、软件工程、游戏架构、玩法系统。
- **D2 熟练应用**：能读懂官方文档和源码，正确使用，能在游戏项目中调试和扩展。用于数据库、编译原理、计算机体系结构、图形学、AI、工具开发。
- **D1 建立地图**：理解概念、输入输出与适用场景，能判断何时深入。用于与当前目标弱相关或偏专门化的选修课。

## 推荐节奏

按每周约 8–12 小时设计，不要求固定学期；每个阶段以“出口能力”而不是课时结束为准。

| 阶段 | 主题 | 推荐深度 | 主要出口 |
|---|---|---:|---|
| 0 | 工具链、Git、CMake、调试、读文档 | D2 | 能建立可重复构建的 C++/Unity/UE 项目 |
| 1 | C 与离散/线性数学 | D3 | 内存安全的 C 小型库；能用向量/矩阵表达游戏问题 |
| 2 | 数据结构、算法、面向对象 | D3 | 可测试的容器/图算法；可维护的 C++ gameplay 模块 |
| 3 | 组成原理、体系结构、操作系统 | D2→D3 | 能解释 cache、栈、线程、同步、帧循环和性能数据 |
| 4 | 数据库、网络、软件工程 | D2→D3 | 存档/配置数据方案；多人游戏的权威服务器原型 |
| 5 | 编译原理、程序语言、AI | D2 | 表达式/配置 DSL；状态机、寻路、行为树等 AI 原型 |
| 6 | 图形学、多媒体、引擎基础 | D3 | 2D/3D 渲染与资源管线实验；可诊断的引擎项目 |
| 7 | Unity 肉鸽纵切片 | D3 | 10–15 分钟可重复游玩的核心循环 |
| 8 | UE/大厂工程拓展 | D2→D3 | 用 UE C++/蓝图重建一个系统；理解大型团队分层 |
| 9 | 发行与毕业项目 | D3 | 小以撒 v1.0：打包、测试、商店素材、版本日志 |

### 阶段切换门槛

没有通过当前阶段的出口测试，不进入下一阶段。出口测试必须包含：

1. 口头/书面解释关键机制；
2. 一份可运行的最小实现；
3. 一个故意制造的失败案例和调试记录；
4. 与游戏项目的映射说明；
5. Git 提交、构建命令和复现步骤。

## 引擎策略

- **主线：Unity**。先用 C# 快速验证 2D 肉鸽玩法、内容迭代和工具工作流；不要把 C# 便利误当成对引擎原理的理解。
- **副线：Unreal Engine**。完成第一个可玩的 Unity 纵切片后，再用 UE C++ 与蓝图重建输入、角色、能力/效果或网络中的一个系统，建立大厂常见的模块化和数据驱动意识。
- **无引擎实验**。C++ 控制台、SDL/窗口实验、离线模拟器、网络服务、数据工具优先用于解释原理；若没有必要，不为了“看起来像游戏”而引入引擎。

## 绝不注水的内容规则

每个章节都必须回答至少一个“为什么”与一个“怎么验证”；如果只是在罗列 API、术语或教程链接，应删除或改成实验。课程正文默认按以下比例组织：

- 60% 原理、推导、边界条件、反例；
- 25% 最小实现、调试和性能验证；
- 10% 游戏团队实践与架构取舍；
- 5% 延伸阅读与可选前沿。

前言、目录、学习鸡汤和重复解释不能替代知识正文。
